# راهنمای پنل مدیریت باران

پنل مدیریت در `http://localhost:5173/manage` و پنل سفارش کارکنان در `/staff` است.
این پنل از API واقعی استفاده می‌کند؛ حالت نمایشی نیست و داده‌های ثبت‌شده در دیتابیس ذخیره می‌شوند.

## به‌روزرسانی محیط

اگر با Docker اجرا می‌کنید، از ریشه پروژه:

```powershell
docker compose run --rm --no-deps web npm ci
docker compose up -d
```

اگر فرانت را مستقیماً روی ویندوز اجرا می‌کنید:

```powershell
cd frontend
npm ci
npm run dev
```

API و دیتابیس نیز باید در حال اجرا باشند. یک migration برای هماهنگ‌کردن توضیحات مدل کاربر اضافه شده؛ سرویس API در Compose هنگام شروع آن را اعمال می‌کند. اگر API از قبل روشن است، پس از آماده‌بودن آن `docker compose exec api python manage.py migrate` را اجرا کنید. در اجرای مستقیم بک‌اند نیز `python manage.py migrate` را اجرا کنید. داده‌های رستوران حذف یا بازسازی نمی‌شوند.
کتابخانه QR به وابستگی‌های فرانت اضافه شده؛ در Docker نیز volume مربوط به node_modules باید با `npm ci` به‌روز شود.

## سناریوی اولین راه‌اندازی

1. در `/manage` گزینه «ساخت حساب مالک» را انتخاب کنید، یا با حساب موجود وارد شوید.
2. «ساخت اولین سازمان» را بزنید. نام فارسی و شناسه انگلیسی یکتا مانند `baran-restaurant` وارد کنید.
3. در «شعب»، شعبه مرکزی را با کد `central` و منطقه زمانی `Asia/Tehran` ثبت کنید.
4. در «منوها»، منوی اصلی را با واحد `IRR` بسازید؛ قیمت‌ها برای این واحد به **ریال** هستند. شعبه خالی یعنی منوی مشترک.
5. در «دسته‌بندی‌ها»، دسته غذا و نوشیدنی را به منو اضافه کنید.
6. در «مواد اولیه»، مواد و حساسیت‌زاها را ثبت کنید؛ سپس در «غذاها و نوشیدنی‌ها» محصول، قیمت، لینک تصویر و مواد اولیه را انتخاب کنید.
7. در صورت نیاز، گروه انتخاب، انتخاب‌ها و افزودنی‌های محصول را بسازید.
8. در «قیمت و موجودی شعب»، تعداد یا قیمت اختصاصی هر شعبه را ثبت کنید. مقدار خالی یعنی استفاده از تنظیمات اصلی یا موجودی نامحدود.
9. در «میزها و QR»، میز بسازید و **همان لحظه لینک یا تصویر QR را ذخیره کنید**. فقط hash توکن در دیتابیس می‌ماند؛ برای لینک گم‌شده باید QR را تعویض کنید و چاپ قبلی را کنار بگذارید.
10. در «کارکنان»، ایمیل، نام، رمز اولیه، نقش و شعب مجاز را وارد کنید. حساب‌های صندوق‌دار، آشپز، سالن‌کار و مدیر شعبه به تخصیص شعبه نیاز دارند.
11. برای افزودن حساب موجود، فقط شناسه حساب و نقش/شعب را وارد کنید؛ نام، ایمیل و رمز جدید را خالی بگذارید. مشخصات یا رمز حساب موجود تغییر نمی‌کند. شناسه حساب از پاسخ `/api/v1/auth/me/` برای خود کاربر قابل دریافت است.
12. لینک میز را در تب جداگانه باز کنید و یک سفارش ثبت کنید. در `/staff` با مالک یا کارکنان وارد شوید و چرخه سفارش و پرداخت را بررسی کنید.

## سایر بخش‌ها

- تخفیف‌ها: کد، نوع ثابت یا درصدی، زمان شروع/پایان و سقف استفاده.
- زمان‌بندی منو: انتخاب روزهای هفته و بازه ساعت در همان روز؛ ساعت‌ها در نسخه فعلی مطابق منطقه زمانی سرور هستند (پیش‌فرض UTC).
- انبار: موجودی اولیه، واحد و حد هشدار؛ تغییر موجودی از «اصلاح موجودی» با مقدار مثبت/منفی و دلیل انجام می‌شود و سند تغییر ایجاد می‌کند.
- دستور مصرف: اتصال محصول به مواد انبار و مقدار مصرف هر واحد محصول.
- رزروها: ثبت، ویرایش و پیگیری وضعیت رزروها؛ تاریخ و ساعت فرم مطابق ساعت محلی مرورگر است.

## دسترسی و حفاظت از داده

- مالک و مدیر سازمان به مدیریت سازمان، شعب و عضویت کارکنان دسترسی دارند.
- مدیر شعبه فقط شعب تخصیص‌یافته و منابع مربوط به آنها را مدیریت می‌کند؛ اجازه ساخت شعبه یا مدیریت کارکنان ندارد.
- فقط مالک می‌تواند مالک دیگری را تغییر دهد یا نقش مالک بدهد. حذف/تنزل نقش خود و حذف آخرین مالک مسدود است.
- تغییر کارکنان مربوط به عضویت همین سازمان است؛ حساب مشترک کاربر در سازمان‌های دیگر دست‌کاری نمی‌شود.
- حذف نیازمند تأیید است. برای حفظ سابقه، در موارد دارای گزینه فعال/غیرفعال، غیرفعال‌سازی ترجیح دارد. بعضی رکوردهای وابسته به سوابق مالی/انبار اصلاً قابل حذف نیستند.
- اطلاعات نشست مدیریت در sessionStorage همان تب نگهداری می‌شود. نشست منقضی‌شده با refresh token تمدید می‌شود؛ در صورت نامعتبرشدن آن، ورود مجدد لازم است.
- فهرست عمومی منو تا ۳۰ ثانیه cache دارد؛ تغییرات ممکن است با این تأخیر دیده شوند.
- برای تست QR روی تلفن، `localhost` قابل استفاده نیست: فرانت و API باید با آدرس شبکه قابل دسترس باشند و CORS و آدرس API متناسب تنظیم شوند. QR را از همان آدرس قابل دسترسی شبکه بسازید.
- تصویر محصول فعلاً با **لینک تصویر** ثبت می‌شود؛ آپلود فایل و ذخیره‌سازی ابری در این تغییر اضافه نشده است.

## تست‌ها

```powershell
docker compose run --rm --no-deps api python -m pytest -q
cd frontend
node node_modules/vitest/vitest.mjs run
npm run build
```

تست‌های بک‌اند از دیتابیس تست SQLite استفاده می‌کنند و داده‌های عملیاتی را تغییر نمی‌دهند.
